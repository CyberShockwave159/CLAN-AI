# clan_ai — Agent Notes

Flutter (Dart SDK ^3.13) cross-platform llama.cpp client — OpenAI-compatible endpoints (llama.cpp llama-server and any OpenAI-compatible backend). Platforms: Linux/macOS/Windows/Android/iOS/Web(PWA — Beta). Deep architecture: `ARCHITECTURE.md`. Features/setup/installer docs: `README.md`. This file only covers what an agent would otherwise get wrong.

## Commands
```
flutter pub get          # required after every git pull
flutter analyze          # lint + typecheck (flutter_lints)
flutter test             # 38 test files, 735 tests, all hermetic
flutter test test/domain/generation_params_test.dart   # single file
flutter test test/integration/   # suite subset
flutter run -d linux     # linux | macos | windows | <android-id> | chrome
```
Windows packaging: `.github/workflows/build-windows.yml` is the *only* Windows workflow — it builds on pushes/PRs to `main` and publishes a GitHub Release on `v*` tags (build → MSIX via `dart run msix:create` → NSIS). The NSIS script must **embed** the MSIX with `File`; a runtime `CopyFiles` produces a tiny installer with no payload that fails on user machines. `version` in `pubspec.yaml` is the single source of truth for the MSIX version (`msix_version` intentionally omitted); `msix_config.yaml` is **not** read by the msix tool (it only reads `pubspec.yaml`). `scripts/build-windows-installer.{bat,sh}` produce `dist/` locally.

## Architecture (what's non-standard)
- **Hybrid MVVM with `Provider` + `ChangeNotifier`; no codegen.** All JSON serialization is manual `toMap()`/`fromMap()`. No domain-layer interfaces — `lib/domain/models/` has only `generation_params.dart` (payloads, RAG params, TextSanitizer).
- **Wiring in `lib/main.dart`**: 4 `ChangeNotifierProvider`s (Settings, Chat, Roleplay, PersonaTemplate) + `Provider<CharacterRepository>`, all constructor-injected. The network stack is a single shared `ApiHttpClient` → `LatencyMeter` → `LlamaApiService` → repos; required deps are **positional initializing formals** (`ChatRepository(this._apiService, {localDb})`, `ChatViewModel(this._chatRepository)`, etc.) with **no `??` fallbacks** — don't reintroduce them, or connection pooling/latency tracking silently forks. `localDb` may still fall back to the `LocalDatabase.instance` singleton. SQLite FFI initialized **once** (`_initSqliteFfi()`, desktop only — calling `sqfliteFfiInit()` again warns "changing sqflite default factory").
- **Shared logic lives in mixins/widgets under `lib/ui/shared/`**, not in the VMs: `stream_mutation_mixin.dart` (streaming, 20ms UI throttle, 5s undo, stopGeneration, switchVariant — used by BOTH Chat and Roleplay VMs), `auto_scroll_mixin.dart` (opt-out auto-scroll), `parameter_sheet_opener.dart` (accepts `isRoleplay`), `drawer_export_menu.dart`, `desktop_keyboard_shortcuts.dart`. Any streaming/undo/branching change goes in the mixin, not the VMs.
- **Thread isolation**: `ChatThread.characterId == null` = assistant, set = roleplay. `getAssistantThreads()` filters out roleplay threads; Roleplay VMs filter in and reuse existing threads per character (`getThreadsForCharacter`) — never create duplicates.
- **Profile vs config split**: `ServerProfile` = connection details (`baseUrl`, `apiKey`, per-profile `reasoning`). `ServerConfig` = global (system prompt, params, model). `syncConfigFromProfile`/`syncProfileFromConfig` propagate connection fields both ways.
- **Settings sections** in `lib/ui/features/settings/views/sections/` are shared across modes. Model dropdown lives in the Profile section; System Prompt section is hidden in roleplay mode (Persona Templates shown instead); Theme section always last.
- **Assistant content rendering** (`DynamicMarkdownView` + `TextSanitizer`): hyperlinks open in the platform browser (new tab on PWA); raster image URLs render inline via `MarkdownImageView` (cached, tap → lightbox) — this includes `data:image/…` URLs (A-PROX `inline_data_url` artifacts), decoded via `Image.memory`; fenced code blocks show only the language in the header (first line stays in the body). Generated **files** render as distinct `ArtifactFileCard` objects at the end of the message: `TextSanitizer.extractFileRefs` lifts non-image artifact-extension URLs (`TextSanitizer.artifactExtensions`, excludes code blocks and `![…]` images, deduped) and merges the stored A-PROX `file_url` artifact (deduped by filename); tapping a card saves/exports via `FileSaver.saveBytes` (stored bytes read from the store, content URLs fetched on demand). Image/file artifact downloads all flow through `MessageAttachmentStore.fetchBytes`, which also decodes base64/percent-encoded `data:` URLs without a network call — so A-PROX `inline_data_url` works even when `/images`/`/files` is unreachable. Only assistant messages render file objects.

## Storage & schema
- `clan_ai.db` schema **v16** (`lib/data/datasources/local_storage.dart`): threads (custom_params, branch_from_thread_id, character_id), messages (is_edited, rag_memory_*, reasoning_content, variant_index/total_variants/sibling_ids, image_path, file_path, file_name, file_mime), characters (+ `appearance`, `identity_portrait_data`, `visual_theme` — image-consistency state, v16), persona_templates. Message image attachments are stored as files on disk via `MessageAttachmentStore` with only the absolute file path in `messages.image_path`; the OpenAI payload embeds them as base64 `image_url` content parts. Character avatars are stored inline as `avatar_data` BLOBs. Migration guards check `PRAGMA table_info` before every `ALTER TABLE`. Schema errors → delete the `.db` files.
- **FK enforcement is on** (`PRAGMA foreign_keys = ON` in `onConfigure`) — messages→threads `ON DELETE CASCADE` is live; `deleteThread` also deletes messages explicitly. Thread search is a single assistant-scoped SQL query (`LocalDatabase.searchThreads`, LIKE wildcards escaped) — don't rebuild the old per-thread N+1 loop.
- `clan_ai_vectors.db` schema **v2** (`vector_store.dart`): `thread_id` added v1→v2. Separate DB from main SQLite. (Its self-referential FK is intentionally not enforced — don't add `PRAGMA foreign_keys` there.)
- SharedPreferences: server profiles, active profile, active config, theme mode/colors, app mode, last roleplay thread, system prompt templates. API keys: `flutter_secure_storage` (Keychain/KeyStore/Secret Service).
- **`Mutex` serializes read-modify-write only in `ServerRepository` and `SystemPromptTemplatesRepository`** (both SharedPreferences-backed) — not in SQLite-backed repos.
- Avatars are stored inline as BLOBs in `characters.avatar_data` — there is no file-based avatar storage. `characters.identity_portrait_data` (a generated reference portrait, ≤512px JPEG) follows the same inline-BLOB pattern; `appearance` and `visual_theme` are plain columns. `ServerProfile.capabilities` is deliberately **not** serialized — it describes the server reachable now and is re-derived by the 15s health poll from A-PROX's `/health` `capabilities` array. Message image attachments *and* A-PROX file artifacts both use on-disk storage via `MessageAttachmentStore` (only the absolute path / opaque ref lives in SQLite).

## Streaming flow (critical for chat changes)
1. VM persists user message → creates streaming placeholder → resolves effective system prompt: `thread.systemPrompt ?? config.systemPrompt`; roleplay uses RAG builder per-message; character `systemPrompt` overrides everything (`{{original}}` prefix prepends the standard prompt); `postHistoryInstructions` appended.
2. `LlamaApiService` context-fits: caps `contextSize` to model capacity minus `reservedOutputTokensDefault` (512) when maxTokens is 0. `serverConfig.reasoning` is passed into params.
3. `SseClient.parseStream()` handles OpenAI delta chunks; `filterReasoning()` extracts reasoning fields (`reasoning`/`reasoning_content`/`thought`) and inline tags (```xml, `<thought>`, `<reasoning>`).
4. Throttle timer (20ms) flushes content + reasoning buffers; looks up the message by ID each tick (handles mutations). Final metrics + `reasoningContent` saved to SQLite on completion.

### Artifact-only chunks must pass through `filterReasoning`
`SseClient.filterReasoning` yields only in response to text or reasoning, attaching artifacts to those yields via `_copyArtifacts`. A chunk carrying `image_url`/`file_url` but **no** text therefore produced no yield and was silently dropped. This was invisible while A-PROX also streamed a caption (the artifact rode along on a text-bearing chunk); A-PROX `image_only` mode sends the image event and *nothing else*, which reduced the response to a single artifact-only chunk and made the client report "the server returned no image" while the server had generated and served a valid image. `filterReasoning` now passes such chunks through. **When adding a new pass-through in that transform, check whether an artifact-only chunk can reach it.**

## Branching / variants
Regenerate/edit truncates at the parent, creates sibling variants via `parentId`/`variantIndex`/`siblingIds`. `getMessagesForThread()` dedupes to the latest variant per group (prevents duplicates after reload); `getAllMessagesForThread()` bypasses dedup for variant navigation. Only messages with same `parentId` and `role == assistant` count as variants. Navigation: sort siblings by `variantIndex`, index into sorted list, next = `variantIndex + 1`. Branch threads link via `branchFromThreadId`.
**A variant group is one consistent snapshot: every member carries the same `siblingIds` (including itself) and the same `totalVariants`, always derived from the ids actually stored — never by incrementing.** `_syncVariantGroup` writes this and `variantGroupFields` gives the same values to a not-yet-persisted message; use both from any code that adds or removes a variant. Three separate bugs came from partial updates: siblings were given new `siblingIds` but kept a stale `totalVariants` (the navigator's count *and* its next-button enabled state both read that field, so the arrow looked live but did nothing); `doRevertVariant` restored the original still listing the deleted id; and `doSwitchVariant` used `orElse: () => currentMsg` for unresolvable ids, manufacturing a duplicate with the same `variantIndex` so the switch no-opped. `doSwitchVariant` now drops unresolved ids and sorts the resolved list. Groups written by the old code remain malformed until the next regeneration in that group rewrites them.

## RAG (roleplay only)
**Two mutually exclusive backends.** Never write embeddings *and* ingest a turn — running both injects the same facts twice.

- **Client** (`ServerConfig.serverSideRagEnabled == false`, the default): pure-Dart 256-dim trigram hash embeddings (`HashEmbedding`, no ML deps), stored per `character_id` + `thread_id`. `RoleplayContextBuilder.build()` searches and injects memories into the *system prompt*; embeddings are written fire-and-forget from the streaming `onComplete` hook. `searchSimilar(threadIds:)` must be scoped to the thread lineage (`getThreadLineageIds()`) — `editUserPrompt` and `deleteMessage` used to omit this and leaked sibling-branch memories; don't reintroduce that. `CharacterMemoriesDialog` lists/prunes embeddings per character.
- **Server** (`serverSideRagEnabled == true` **and** `ServerProfile.isAprox`): retrieval happens inside A-PROX via the `a-prox-rag` model alias plus a `rag: {collection, top_k, min_score}` request object, and completed turns are pushed with `AproxRagClient.ingest` (fire-and-forget, from the `onComplete` hook). The local builder is skipped entirely and `RoleplayContext.withoutMemories` is used so nothing local leaks into the prompt. Collections are per character **and** per thread (`clan_<charId>_<threadId>`) because A-PROX searches *every* collection when unfiltered. Note A-PROX prepends its context to the **last user message**, not the system prompt.
- The server path needs the live `ServerConfig`/`ServerProfile`, so every VM method that switches on the backend takes them as parameters (`serverConfig`, `connection`) — follow that; don't cache the choice in a field.
- `roleplayMode: true` on `RequestOptions` tags **every** message (including the system prompt) with `"roleplay": true`, which makes A-PROX restrict armed tools to `rag_search`/`rag_ingest`/`image_generate`. All A-PROX request fields ride on `RequestOptions` (`lib/data/datasources/request_options.dart`): `modelOverride`, `rag`, `extraBody` (e.g. `image_style`), `roleplayMode`, `referenceImage`. Defaults are inert, so non-A-PROX requests are byte-for-byte unchanged.
- Auxiliary one-shot calls (scene-prompt drafting, appearance drafting, style detection) go through `ChatRepository.completeOnce` — non-streaming, never persisted, never streamed into the UI, never written to RAG. Their instruction turns are prefixed `/bypass` so A-PROX's image-request detection can't trip on a prompt containing "draw"/"picture" and silently burn a generation.

## Roleplay gotchas
- First assistant message (character's greeting) has regenerate disabled until the user has replied.
- Alternate greetings show as chips above input only while all messages are assistant; selecting one **always creates a new thread** (`startRoleplayWithGreeting`).
- Editing assistant messages only allowed for the **last** message — requires `onEditAssistant` + `isLastMessage` (`index == messages.length - 1`) passed from the parent.
- `RoleplayPromptFormatter.buildSystemPrompt()` appends the identity guard ("Never speak, think, act, or write dialogue for the user…") to every prompt — sole location for roleplay behavior rules.
- **Scene image generation is a variant, not a new message.** `doCreateImageVariant` (in `stream_mutation_mixin.dart`) mirrors `doRegenerateMessage`'s bookkeeping but seeds `content` from the target and does **not** inherit its `imagePath`, so each press is an independent generation from the identity reference. The stream runs with `StreamTextMode.discard` so A-PROX's picture caption never overwrites the character's dialogue. On failure call `doRevertVariant` — never leave an image-less placeholder. Image variants are excluded from BOTH RAG backends: a caption and an image prompt must never enter memory.
- **The `/image` request is built by hand**, not from thread history: `SceneImagePrompts.buildSceneHistory` returns the last few messages plus a synthetic `/image` turn, passed as `historyOverride`. The identity reference rides in `RequestOptions.referenceImage`, which the transport attaches to the final user message as **array content** — A-PROX's `extract_reference_image` reads only array content, and only off the latest user turn, so a plain string is silently ignored and the request degrades to text-to-image.
- **Reference images must be PNG/JPEG/WebP.** A-PROX sniffs magic bytes and silently falls through to text-to-image for anything else — an AVIF avatar produces a plausible image that ignored the reference, with no error to explain why. `IdentityReferenceResolver.normalizeForReference` transcodes and downscales, and returns the input unchanged when it cannot decode, so a corrupt reference degrades rather than failing.
- **Auxiliary one-shot calls** (`ChatRepository.completeOnce`) each pick their own `reasoning` / `maxTokens` / `timeout`. The cheap ones (appearance draft, style detect) run with reasoning **off** and a 256-token budget. The scene-image prompt draft is the exception: reasoning **on**, 16384 tokens (`SceneImagePrompts.draftMaxTokens`) and a 10-minute `draftTimeout` — with the channel off, a reasoning model narrates into `content`, which then shares the budget with the prompt and gets truncated mid-sentence. Truncation there has caused a silent no-image failure. Don't lower these without re-testing against a live reasoning model.
- **A long `completeOnce` MUST raise `timeout`.** The shared `ApiHttpClient` receive budget is 60s, and `post` enforces it. A reasoning call that overruns it is aborted client-side *even though the server already answered*, and the failure surfaces as a blank result with no error — it looks like the model returned nothing. Observed at 62s. Any call with a `maxTokens` ceiling above a few thousand needs its own `timeout`.
- **Scene image requests set `image_only`.** They stream with `StreamTextMode.discard`, so A-PROX's vision-caption turn and final synthesis turn are pure cost (~85s on a 35B model). `RequestOptions.sceneImage` sets it; don't "simplify" it away.
- **Style must be enforced at the workflow level, not in the prompt.** A-PROX's prompt enhancer rewrites the prompt, so a style phrase in the prompt text is at the mercy of a rewriter. Send `image_style` as well; A-PROX resolves it against `[image_generation.styles]` when it builds the ComfyUI graph, after the rewrite.
- Character delete in roleplay drawer: `await` delete → `roleplayVM.deleteCharacter(id)` (clears thread cache) → pop → `setState`, or the `FutureBuilder` snapshot stays stale.
- Async handlers (delete/import/nav): always check `context.mounted` after `await` before using `ScaffoldMessenger`/`Navigator`.

## Platform / env gotchas
- Android networking: `127.0.0.1` is device loopback — use `10.0.2.2` (emulator) or LAN IP (physical device).
- Native SQLite is bundled automatically: `sqflite_common_ffi` resolves `sqlite3` **3.x**, whose Dart build hook emits `libsqlite3` as a native asset per target (see `.dart_tool/flutter_build/*/native_assets.json`). Do **not** add `sqlite3_flutter_libs` — `0.6.0+eol` is an empty stub and `0.5.x` is the legacy sqlite3 2.x path.
- HTTP timeouts 10s connect / 60s receive: the connect phase is bounded by `HttpClient.connectionTimeout` (real TCP/TLS timeout). The `.timeout()` guards cover receive: GET health/model calls use the 10s connect budget for the whole call; `post` and the streaming `postStream` header-wait use the 60s receive budget. `postStream` takes a `timeout` override for requests whose server withholds headers for minutes: A-PROX `/image` stops llama.cpp, cold-starts ComfyUI, runs the diffusion job and restarts llama.cpp before emitting anything (~195s measured), so `RequestOptions.sceneImageStreamTimeout` (10 min) applies. Keepalives (`: keepalive` every 2s) do **not** save you here — they keep the socket warm but the job still has to finish. `send()` resolves on response *headers*, which on a busy/slow server includes slot queueing + prefill — a 10s header bound made remote servers with a healthy link falsely report "connection" failures, so keep the receive budget there. `throwForStatusCode` extracts messages from `error`/`message`/`detail`/nested shapes. Error mapping: 400 + "context"/"exceed" → `ContextLimitExceededException`; 500 + "memory"/"slot" → `ServerOOMException`; else `AppException`.
- Health polling every 15s, fallback `/health` → `/props` → `/v1/models`, model list deduped by id. The `/health` response doubles as the A-PROX capability probe (`PingResult.parseCapabilities`); gate every A-PROX-only feature on `ServerProfile.isAprox` / `supportsImageGeneration` rather than assuming the backend.
- Keyboard shortcuts (`DesktopKeyboardShortcuts`, uses `KeyboardListener`): Ctrl+N new chat, Ctrl+K thread search (`SearchDelegate` over `searchThreads()`), Ctrl+, settings, Esc stop, Ctrl+/ or F1 help. The widget sits *above* `MaterialApp`, so it receives the app's `navigatorKey` via constructor (no static global) to reach a context below the Navigator for `showDialog`/`showSearch`.
- Theme: dark default; `AppThemeMode` dark/light/custom with `CustomThemeColors` presets (warm/cool/pastel); lookup via `context.clanX` ThemeExtension.
- `analysis_options.yaml` excludes platform/build dirs. Do not downgrade Dart SDK below ^3.13.
